## 7. Product Features

### Authentication
- User registration (name, email, password) with validation
- Login with JWT access + refresh tokens
- Auto-login on app restart (token persistence)
- Logout clears stored credentials

### AI Chat
- Real-time chat with Wandy AI (Gemini-backed)
- Session persistence across messages
- Quick action chips for common queries
- RAG-enhanced responses with source citations

### Trip Management
- Create trip: name, destination, dates, budget, travel style, interests
- View trip list (user-scoped)
- Trip detail with itinerary timeline view
- Edit/delete trips (owner only)
- Soft delete with recovery capability

### AI Trip Planner
- Generate structured itinerary from TripContext via Gemini
- Deterministic budget validation (code-computed, not AI-computed)
- Preview modal before saving
- Overwrite warning for existing itineraries
- Bulk transactional save (`prisma.$transaction`)
- AI CANNOT directly write to database

### Real Data Pipeline
- OSM POI collection via Overpass API
- Entity resolution (fuzzy name + geographic proximity)
- Canonical places dataset with provenance
- Quality validation with bounding-box checks

## 15. Technical Decisions

| Decision | Rationale | ADR |
|----------|-----------|-----|
| AI cannot write directly to DB | User must confirm itinerary before save; prevents hallucinated data from persisting | — |
| Deterministic budget validation | AI-generated cost figures are re-computed by Python code to ensure arithmetic correctness | — |
| Bulk itinerary save via `$transaction` | All-or-nothing persistence; partial writes could corrupt trip state | — |
| `paraphrase-multilingual-MiniLM-L12-v2` for RAG | 384-dim, supports 50+ languages including Vietnamese, good quality/speed tradeoff | — |
| HNSW index on pgvector | O(log n) approximate nearest neighbor, suitable for 628→100K+ chunks | — |
| MostPop as recommendation baseline | Simplest non-trivial recommender; all future models must beat this threshold | — |
| Temporal leave-last-one-out evaluation | Realistic evaluation protocol that respects time ordering of interactions | — |
| Separate dataset roles | ViHoRec=recommendation, VLSP=ABSA, ViMACSA=multimodal; prevents role confusion | ADR-004 |
| TripContext schema extension | Structured context enables deterministic validation of AI outputs | ADR-003 |
| OSM + Entity Resolution pipeline | Real data with provenance; entity resolution prevents duplicate places | ADR-002 |

## 16. Problems Found

1. **UIT-VSFC false claim** — Prior documentation incorrectly stated 9 review records came from UIT-VSFC. The actual corpus contains student feedback, not travel reviews.
2. **ViHoRec column name mismatch** — `interactions.csv` uses `user_id`/`hotel_id` but benchmark CSVs use `userID`/`itemID`. Required normalization in loader.
3. **ViHoRec interaction count mismatch** — Paper claims 18,267 interactions; actual CSV contains 17,911. Documented actual count.
4. **Root `.gitignore` null-byte corruption** — Line 39 contained `\x00` bytes from prior edits.
5. **Prisma `vector` type unsupported** — Prisma ORM doesn't natively support pgvector's `vector(384)` type; required raw SQL `ALTER TABLE`.
6. **Windows encoding** — `sys.stdout` defaults to `cp1252`; Vietnamese characters fail without `reconfigure(encoding="utf-8")`.

## 17. Problems Fixed

1. **UIT-VSFC claim** — Retracted false academic citation; created `review-provenance.json` documenting synthetic origin.
2. **ViHoRec columns** — `ViHoRecLoader.normalize()` maps `userID`→`user_id`, `itemID`→`hotel_id`, `location`→`city`.
3. **`.gitignore` corruption** — Cleaned null bytes; added proper data governance rules.
4. **pgvector column** — Applied via raw SQL: `ALTER TABLE documents ADD COLUMN IF NOT EXISTS embedding vector(384)`.
5. **`config.py` empty default** — Changed `DATABASE_URL` default from `""` to `"postgresql://postgres:postgres@localhost:5432/wanderai"`.
